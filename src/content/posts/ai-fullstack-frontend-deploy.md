지난 1편에서는 데이터베이스와 백엔드 영역에서 <strong>Standard SQL(표준 SQL)</strong>과 스키마-퍼스트 접근법이 AI 에이전트에게 왜 유리한지 살펴보았습니다. 명확한 스키마가 존재할 때 AI는 환각 없이 정확한 코드를 작성할 수 있었습니다.

이번 2편에서는 프론트엔드와 배포 파이프라인으로 시야를 넓혀봅니다. 프론트엔드는 백엔드에 비해 패턴이 파편화되어 있고 선택지가 다양합니다. 이런 환경에서 AI 에이전트가 코드베이스를 더 잘 이해하고 예측 가능한 코드를 생성하게 만들려면 어떤 구조를 선택해야 할까요?

프론트엔드와 배포에서 AI에게 가장 중요한 힌트는 바로 '컨벤션(Convention)'입니다. <strong>"컨벤션이 곧 컨텍스트다"</strong>라는 명제 아래, AI 친화적인 프론트엔드와 배포 아키텍처를 살펴보겠습니다.

---

## 1. 프레임워크 선택 — 컨벤션이 곧 컨텍스트

프레임워크의 구조적 제약은 인간 개발자에게는 답답하게 느껴질 수 있지만, AI에게는 완벽한 가이드라인이 됩니다. 폴더 구조가 라우팅을 결정하고, 파일명이 역할을 부여하는 컨벤션 기반 프레임워크는 AI에게 명확한 컨텍스트를 제공합니다. AI 모델들은 이미 주요 프레임워크의 공식 문서를 깊게 학습했으므로, 컨벤션이 강한 환경일수록 더 높은 품질의 코드를 생성해 냅니다.

### 주요 프레임워크 비교

**Next.js App Router**
파일 기반 라우팅 시스템은 AI에게 화면의 구조를 명확히 알려줍니다. 특히 App Router의 `page.tsx`, `layout.tsx`, `route.ts` 같은 정해진 파일명은 역할이 뚜렷합니다. <strong>React Server Components(RSC)</strong>와 클라이언트 컴포넌트(`"use client"`)의 명시적인 경계는 AI가 데이터 패칭과 상호작용의 렌더링 전략을 올바르게 선택하도록 유도합니다.

**Astro**
콘텐츠를 중심에 두는 사이트에 최적화된 프레임워크입니다. Astro의 강력한 점은 `Content Collections`를 통해 콘텐츠의 프론트매터 스키마를 TypeScript로 명확히 정의할 수 있다는 것입니다. 또한 <strong>Islands Architecture(아일랜드 아키텍처)</strong>를 통해 정적 HTML 위에 인터랙티브한 JavaScript가 필요한 부분만 명시적으로 선언(`client:load` 등)하므로, AI가 성능을 고려한 코드를 작성하기 좋습니다.

**SvelteKit**
컴파일러 기반 접근법을 사용하는 SvelteKit은 런타임 오버헤드가 적습니다. 명시적이고 직관적인 템플릿 문법 덕분에 AI가 보일러플레이트 코드 없이 핵심 로직을 바로 작성할 수 있습니다. `+page.svelte`와 `+page.server.ts` 같은 파일명 컨벤션은 프론트엔드와 백엔드 간의 데이터 흐름을 명확하게 분리하여 에이전트가 데이터 로더를 쉽게 구성할 수 있게 합니다.

| 프레임워크 | 라우팅 컨벤션 | AI 예측 가능성 | 번들 특성 | 적합 케이스 |
|---|---|---|---|---|
| **Next.js** | App Router (`page.tsx`) | 매우 높음 (데이터 풍부) | RSC, 클라이언트 번들 | 동적 앱, SaaS |
| **Astro** | File-based (`.astro`) | 높음 (명시적 JS 경계) | 제로 JS, 아일랜드 | 블로그, 마케팅 사이트 |
| **SvelteKit** | Directory-based (`+page`) | 보통&#126;높음 | 소형 컴파일 번들 | 고성능 대시보드 |

### AI 스캐폴딩 도구와 생태계

현재 AI 코드 생성 도구의 발전 방향은 프레임워크 선택에 큰 힌트를 줍니다.
- Vercel의 **v0.dev**: React 컴포넌트와 Next.js 기반 UI를 즉석에서 생성합니다.
- **Lovable**, **Bolt.new**: 프롬프트만으로 전체 애플리케이션을 스캐폴딩하며, 대부분 React 기반 생태계를 기본값으로 사용합니다.

이러한 도구들이 기본적으로 전제하는 생태계가 현재 AI 코드 생성의 '표준 패턴'으로 자리 잡고 있습니다. AI 툴링의 지원을 극대화하려면 주류 프레임워크의 컨벤션을 따르는 것이 유리합니다.

## 2. 배포 플랫폼 — "제로 컨피그"와 AI 생성 코드의 적합성

인프라 구성은 AI가 가장 어려워하는 영역 중 하나입니다. 복잡한 파이프라인이나 서버 설정 대신, 저장소 연결만으로 배포가 완료되는 '제로 컨피그(Zero Config)' 플랫폼이 AI 기반 개발 속도에 부합합니다.

| 특성 | Vercel | Cloudflare Pages | Netlify |
|---|---|---|---|
| **최적 대상** | Next.js 풀스택 앱 | 글로벌 엣지 성능, 비용 효율 | 정적 사이트, JAMstack |
| **엣지 네트워크** | 글로벌 (Next.js 최적화) | 330+ 로케이션 (최대 규모) | CDN 기반 |
| **가격 모델** | 사용량 기반 (급증 가능) | 대역폭 무료 (예측 가능) | 크레딧 기반 (균형) |
| **AI 코딩 시너지** | v0.dev 생성 코드 기본 배포지 | Workers 생태계 (학습 곡선) | 프레임워크 중립 지원 |
| **프리뷰 배포** | ✅ Git 커밋별 자동 생성 | ✅ 지원 | ✅ 지원 |

**AI 생성 코드의 배포 마찰 최소화**
Vercel은 Next.js와의 강력한 결합을 통해 AI가 생성한 코드를 마찰 없이 배포할 수 있는 최적의 환경을 제공합니다. `v0.dev` 같은 도구에서 만들어진 코드는 추가 설정 없이 인프라에 최적화되어 동작합니다. Cloudflare Pages는 비용 효율적이지만, <strong>Cloudflare Workers(워커)</strong> 특유의 런타임 제약으로 인해 AI가 생성한 특정 Node.js 패키지가 동작하지 않을 수 있어 주의가 필요합니다.

**프리뷰 배포의 중요성**
PR마다 독립적인 환경을 제공하는 프리뷰 배포는 필수적입니다. AI가 작성한 코드를 머지하기 전에 샌드박스 환경에서 즉각적으로 검증할 수 있어야 안정적인 협업이 가능하며, 세 플랫폼 모두 이를 훌륭하게 지원합니다.

**비용 예측성**
AI가 생성한 앱은 무한 루프 등 결함으로 서버리스 함수 사용량을 급증시킬 위험이 있습니다. 대역폭 비용이 예측 가능한 Cloudflare Pages는 이런 리스크를 줄일 수 있는 대안입니다.

## 3. 모노레포 — AI의 단일 컨텍스트

AI 에이전트가 시스템 전체를 이해하려면 컨텍스트 윈도우 내에 필요한 모든 정보가 존재해야 합니다. 멀티레포에서는 AI가 다른 레포의 인터페이스를 추측해야 하므로 오류가 증가합니다. 모노레포는 AI에게 전체 프로젝트를 하나의 단일 컨텍스트로 제공하는 최적의 구조입니다.

### 표준 모노레포 구조

```text
my-monorepo/
├── apps/
│   ├── web/               # Frontend (Next.js, Vite)
│   └── api/               # Backend (Hono, Express)
├── packages/
│   ├── ui/                # 공유 UI 컴포넌트
│   ├── types/             # 공유 TypeScript 타입
│   ├── database/          # ORM 스키마 & 클라이언트
│   └── config/            # 공유 설정 (tsconfig, eslint)
├── docs/                  # 아키텍처, 스펙 문서
├── AGENTS.md              # AI 에이전트 컨텍스트 규칙
├── pnpm-workspace.yaml
├── turbo.json
└── package.json
```

**시맨틱 메타데이터로서의 디렉토리**
이름 자체가 AI에게 강력한 힌트가 됩니다.
- `packages/database/`: 데이터 모델의 단일 진실 공급원입니다. AI가 UI를 수정할 때 이곳을 참조하게 하면 일관성이 유지됩니다.
- `packages/types/`: 프론트엔드와 백엔드 간의 공유 계약입니다. 양쪽 통신 규격을 파악하는 기준점이 됩니다.
- `AGENTS.md`: AI가 참조해야 할 코딩 규칙과 아키텍처 결정을 명시하는 컨텍스트 문서입니다.

**도구 선택: Turborepo와 pnpm**
- **Turborepo**: 복잡한 의존성 아래서도 빌드 캐싱과 병렬 실행을 통해 AI의 피드백 루프 속도를 높여줍니다.
- **pnpm**: 엄격한 의존성 트리 관리로 팬텀 디펜던시를 방지하여, AI가 잘못된 모듈을 가져오는 실수를 차단합니다.

## 마무리

AI가 코드를 작성하는 시대의 아키텍처는 에이전트가 쉽게 추론할 수 있는 환경을 만드는 것이 핵심입니다. 컨벤션 기반 프레임워크는 명확한 지도가 되고, 제로 컨피그 배포는 실험 속도를 올립니다. 모노레포는 파편화된 코드를 모아 단일 컨텍스트를 제공함으로써 예측 가능성을 극대화합니다.

이어지는 3편에서는 마지막으로 <strong>"설계 원칙과 보안"</strong>을 다루며, AI가 코드를 직접 수정하는 환경에서 시스템을 방어적으로 구축하는 방법을 살펴보겠습니다.
